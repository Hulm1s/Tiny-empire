# Tiny Empire

A Unity 6 mobile farm-tycoon game (`game/`), built to WebGL and played on a phone.
The level is generated by script, not hand-placed, so the layout, the economy
numbers and the wiring all live in one readable file.

## Standing rules

- **Never publish without the exact phrase `GO LIVE`.** Approval is per-build and
  is spent once used. Builds otherwise stay local.
- **Do not break the existing architecture.** StationBase, InteractionSquare,
  CarryStack, the shared player/worker interaction system, the customer system,
  SaveIdentity, save/load and the unlock progression all work. Prefer a small
  extension of what exists over a new parallel system.
- **No HUD action buttons.** If something can be a physical place in the world,
  it is an interaction square the player stands in.
- **No mechanic may require money to escape a state where you cannot earn money.**

## Build and verify

Headless, from the repo root. Stop any local server first — it locks the build output.

```bash
"D:/unity/unity engine/6000.1.6f1/Editor/Unity.exe" -quit -batchmode -nographics -projectPath D:/iosGame/game -executeMethod Tycoon.EditorTools.FarmSceneBuilder.Build -logFile D:/iosGame/build-scene.log
```

Then `TycoonBuild.BuildWeb` for the player, `SquareAudit.Run` for the layout audit,
`IconSheet.Export` to render every generated icon to `icon-sheet.png`. Each logs
`SCENE_OK` / `BUILD_OK` / `AUDIT_OK` / `ICONS_OK` on success; grep the log for
`error CS`.

**The layout audit is the main safety net.** It measures every interaction square
and every building footprint in the level's own grid and reports overlaps at day
one and fully built, whether a hire can be bought before its route exists, and
whether the camera can ever see the edge of the ground. Run it after anything
that moves, resizes or adds an object. It has caught faults the eye missed
repeatedly.

`./publish.sh` deploys `docs/` — only ever after `GO LIVE`.

## Model routing

Pick the level by **risk and scope, not by diff size or prompt length**. A long
request with a straightforward implementation is still Level 2.

| Scope | Risk | Level | Agent |
|---|---|---|---|
| isolated | low | 1 | `tweak` |
| isolated | medium | 1–2 | `tweak` or `feature` |
| multi-file | low / medium | 2 | `feature` |
| multi-system | medium | 2 | `feature` |
| cause unknown | medium | 2+ | `debug` |
| multi-system | high | 3 | `architect` |
| architectural | any | 3 | `architect` |

- **`tweak`** (Haiku, low effort) — one isolated change with a known cause: a
  value, a price, a spawn rate, a label, a colour, a position, a scale, one
  contained visual bug.
- **`feature`** (Sonnet, medium) — **the default for real development.** Several
  files or several existing systems: a new building, a production chain, a worker
  or interaction behaviour, customer spawning, economy, progression, offline
  income, save/load, a layout change that must keep routes valid.
- **`debug`** (Sonnet, high) — a bug whose cause is not yet known, in systems
  that are individually understood. Investigation first, fix second.
- **`architect`** (Opus, high) — architecture changes, large refactors across core
  systems, project-wide audits, planning a major system, or a systemic bug that
  survived `debug`.

Opus is **not** the default. Do not reach for it because a task is important, the
prompt is long, or it has many bullet points.

**Escalate rather than push on.** If a level finds the task is bigger than it
looked — the cause is elsewhere, the fix needs the architecture to move, several
systems are involved — it stops and says `ESCALATE:` with what it found, and the
work moves up a level. Do not restart work that a cheaper level already
understood correctly and can safely finish.

**Never route to Fable.** The pool is Haiku → Sonnet → Opus.

**Cheaper never means lower quality.** A cheaper level gets a smaller problem, not
permission to skip reading the existing code, skip verification, or hardcode
around a system that already exists. Every level gets the full context of its
task and is held to everything on this page.

**Manual selection always wins.** "use Haiku" / "use Sonnet" / "use Opus" /
"strongest model" / "cheapest suitable model" override the table.

The models and effort defaults live in `.claude/settings.json`; the four agents
in `.claude/agents/`.

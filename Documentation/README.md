# Tiny Empire — Developer Handover

A complete, self-contained manual for this project. Written so that someone who built it, then did
not touch it for six months — and has no AI assistant — can open it, find anything, change it
safely, test it and release it.

Everything here was read from the live code. Where something could not be established, it says
**UNKNOWN / NEEDS MANUAL VERIFICATION** rather than guessing.

## Project map

**Tiny Empire** is a farm tycoon game for the iPhone. You walk a character around, stand in
painted squares to harvest, feed, collect, repair and sell, and spend the takings unlocking more
farm. Built in **Unity 6000.1.6f1 (URP)** and shipped as a **Web build** installed to the Home
Screen — no App Store, no developer account, no expiry.

```
D:\iosGame\              <- the REPOSITORY (git, docs/, publish.sh)
D:\iosGame\game\         <- the UNITY PROJECT (what Unity Hub opens)
```

| | |
|---|---|
| Runtime code | `game/Assets/_Project/Scripts/` |
| Level builder, audits, build tools | `game/Assets/_Project/Editor/` |
| The only scene | `game/Assets/_Project/Scenes/Farm.unity` — **generated by script** |
| Unity | `D:/unity/unity engine/6000.1.6f1/Editor/Unity.exe` |
| Web build output | `docs/` — gitignored |
| Live site | `https://hulm1s.github.io/Tiny-empire/` (served from `gh-pages`) |
| Blender (characters only) | `D:\Blender\blender.exe` — must be **2.93.2** |

### Three facts that explain most of the project

1. **The level is generated by code**, not hand-placed. `FarmSceneBuilder.cs` is the layout, the
   economy and the wiring in one readable file. There are **no prefabs**.
2. **Everything the player does is "stand in a square."** One class, `StationBase`, serves the
   player and the hired workers identically — a worker is just something with a `CarryStack` that
   walks into a trigger. There are **no HUD action buttons**.
3. **All UI is built in C# at runtime**, including every icon, because the headless build cannot
   import TextMeshPro and the legacy font has no emoji glyphs.

## The four rules

From `CLAUDE.md`, and they govern every change:

1. **Never publish without the exact phrase `GO LIVE`.** Approval is per-build and spent once used.
2. **Do not break the existing architecture.** Prefer a small extension of what exists over a new
   parallel system.
3. **No HUD action buttons.** If it can be a physical place in the world, it is an interaction
   square the player stands in.
4. **No mechanic may require money to escape a state where you cannot earn money.**

Rule 4 is why repairs work at $0, why workers have no wage or running cost, why
the carry stack holds mixed goods, and why there are three bins. Each of those exists because the
alternative produced a real dead end.

## "I have no Claude subscription. What now?"

Everything you need is in this folder. Specifically:

### Open the project
Unity Hub → **Tiny Empire** (`D:\iosGame\game`). Git/GitHub Desktop → `D:\iosGame`.
The scene is `Assets/_Project/Scenes/Farm.unity`.

### Find things
Use **[CHANGE_MAP.md](CHANGE_MAP.md)**. It names the file and line for every tunable in the game.
Failing that, nearly everything is in `FarmSceneBuilder.cs` and it is heavily commented — the
comments explain *why*, including the mistakes that were made first.

### Edit gameplay
**[EDITING_GUIDE.md](EDITING_GUIDE.md)**. Change the number in `FarmSceneBuilder.cs`, then:

```bash
"D:/unity/unity engine/6000.1.6f1/Editor/Unity.exe" -quit -batchmode -nographics -projectPath D:/iosGame/game -executeMethod Tycoon.EditorTools.FarmSceneBuilder.Build -logFile D:/iosGame/build-scene.log
```

Or in the editor: `Tycoon → Rebuild Farm Scene`.

### Edit models
**[CHARACTERS_AND_MODELS.md](CHARACTERS_AND_MODELS.md)**. Blender 2.93.2 only. Edit
`models/pipeline/humanoid_animated.blend`, run `export_unity.py`, then
`Tycoon → Reimport Character Models` and `Tycoon → Verify Character Models`.

### Test
Press **Play in the editor** for almost everything — it is seconds, not minutes. Then
**[TESTING_CHECKLIST.md](TESTING_CHECKLIST.md)**. Run the layout audit after anything that moves:

```bash
"D:/unity/unity engine/6000.1.6f1/Editor/Unity.exe" -quit -batchmode -nographics -projectPath D:/iosGame/game -executeMethod Tycoon.EditorTools.SquareAudit.Run -logFile D:/iosGame/build-audit.log
```

Read `[Audit] Nothing overlaps.` — **not** `AUDIT_OK`, which prints even on failure.

### Build
**Stop any local server first.**

```bash
"D:/unity/unity engine/6000.1.6f1/Editor/Unity.exe" -quit -batchmode -nographics -projectPath D:/iosGame/game -executeMethod Tycoon.EditorTools.TycoonBuild.BuildWeb -logFile D:/iosGame/build-web.log
```

Then test it:

```bash
cd /d/iosGame/docs && python -m http.server 8123
```

Fresh tab, `http://localhost:8123/`. WASD moves. `?debug=1` for an fps readout.

### Deploy
**[RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md)**, then:

```bash
cd /d/iosGame && ./publish.sh
```

Git Bash only. Force-pushes `docs/` to `gh-pages`. Live in a minute or two.

### Roll back
```bash
cd /d/iosGame && git reflog show gh-pages
```

**Run that first, before anything else** — the previous build exists only in the local reflog.
There is no server-side history. Full procedure in `BUILD_AND_DEPLOY.md` §7.

### When something breaks
**[TROUBLESHOOTING.md](TROUBLESHOOTING.md)**. It is organised by symptom and most entries describe
a bug this project has actually had.

## The final release flow

```
EDIT                 FarmSceneBuilder.cs, almost always
  ↓
REBUILD SCENE        Tycoon → Rebuild Farm Scene            -> SCENE_OK
  ↓
AUDIT                Tycoon → Audit Interaction Squares     -> "Nothing overlaps."
  ↓
LOCAL PLAYTEST       press Play in the editor
  ↓                  (loop back to EDIT until the whole batch is done)
  ↓
SET PRICES REAL      FarmSceneBuilder.cs:44 -> 0d, rebuild scene again
  ↓
BUILD                Tycoon → Build Web                     -> BUILD_OK
  ↓                  (stop the local server first!)
LOCAL WEB TEST       python -m http.server 8123, fresh tab
  ↓
FULL CHECK           TESTING_CHECKLIST.md + RELEASE_CHECKLIST.md
  ↓
COMMIT + PUSH        publish.sh records HEAD as provenance
  ↓
DEPLOY               ./publish.sh          <- requires GO LIVE
  ↓
SMOKE TEST           live URL, private window, check the version
```

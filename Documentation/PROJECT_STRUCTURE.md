# PROJECT STRUCTURE

What is where, and what each part is for. This is the architecture document — read it once
properly and the rest of the manual will make sense.

All paths are from the repository root `D:\iosGame\`.

---

## 1. The two roots

```
D:\iosGame\                  <- the REPOSITORY (git, docs, publish script)
D:\iosGame\game\             <- the UNITY PROJECT (this is what Unity Hub opens)
```

This trips people up constantly. **Unity Hub points at `D:\iosGame\game`. Git points at
`D:\iosGame`.** The repository contains the Unity project plus the deployment machinery.

```
D:\iosGame\
├── .claude/                 Claude Code agent + model routing config (not game code)
```

## 3. The single most important architectural fact

**The level is not hand-placed. It is generated by C# code.**

`game/Assets/_Project/Editor/FarmSceneBuilder.cs` builds `Farm.unity` from nothing, every time
you run it. Its own header says why (`FarmSceneBuilder.cs:19-21`):

> The scene is built by script rather than hand-placed so that the layout, the economy numbers
> and the wiring all live in one readable file.

Consequences you must internalise:

- **The layout, every price, every capacity and every production rate are in that one file.**
  Not in the inspector, not in ScriptableObjects (mostly), not in prefabs.
- **There are no prefabs in this project.** Nothing is instanced from a prefab asset; it is all
  constructed at build time by `LevelBuildKit`.
- **Hand-editing the scene in the Unity editor works, but the next rebuild discards it.** That
  is fine for experimenting — copy the numbers you like back into the builder.
- To change the game, you edit the builder and re-run it. See `DEVELOPMENT_WORKFLOW.md`.

## 4. Runtime code — `game/Assets/_Project/Scripts/`

All code is under the `Tycoon.*` namespaces.

### `Core/` — services and persistence (namespace `Tycoon.Core`)

| File | What it is |
|---|---|
| `GameRoot.cs` | Global services holder. **Creates itself before the first scene loads** via `[RuntimeInitializeOnLoadMethod]`, so no scene needs wiring. Owns the `Wallet`, runs the 15-second autosave. |
| `Wallet.cs` | The player's money. The only place currency is mutated, so every income and cost is observable from one `Changed` event. Also holds `MoneyFormat.Short()` (`$1.2K`). |
| `GameClock.cs` | The single time source. Wall-clock Unix seconds, because `Time.time` resets on every page load. Holds `MaxOfflineSeconds = 8h`. |
| `SaveSystem.cs` | The whole save store. One `PlayerPrefs` blob. See `SAVE_SYSTEM.md`. |
| `ISaveable.cs` | The save contract + `SaveKeys.For()`, which builds `<id>#<ComponentType>`. |
| `SaveIdentity.cs` | A stable, builder-assigned id on a GameObject. The reason renaming things does not wipe progress. |
| `ProductRegistry.cs` | What the farm can currently produce. Gates which products customers are allowed to ask for. |
| `IsometricCameraRig.cs` | The orthographic camera that follows the player. Pitch/yaw/zoom live here. `SnapToTarget()` jumps it after a teleport. |
| `Location.cs` | Marks the root of a place (the farm, the supermarket): id, name, arrival `spawnPoint`. The audit walks every one. |
| `NavigationBaker.cs` | Bakes the NavMesh at runtime so workers can path. |

### `Stations/` — the interaction system (namespace `Tycoon.Stations`)

This is the heart of the game. **Everything the player does is "stand in a square".** There are
no HUD action buttons anywhere in the project, deliberately.

| File | What it is |
|---|---|
| `StationBase.cs` | **The core contract.** A trigger volume + an interaction tick. Read this file before changing anything in this folder. |
| `ItemBuffer.cs` | A pile of one kind of goods, with a capacity. Owns spoilage. Saveable. |
| `ProducerMachine.cs` | Consumes an input buffer, fills an output buffer, wears out as it works. Holds the livestock headcount. Saveable. |
| `HarvestStation.cs` | A field. Regrows over time, fills your arms. Saveable. |
| `DepositStation.cs` | Empties your arms into a buffer ("FEED"). |
| `CollectStation.cs` | Fills your arms from a buffer ("COLLECT"). |
| `RegisterStation.cs` | A till. Serves the front customer, pays as it goes. Declares what it `sells`. |
| `SellStation.cs` | Turns carried goods straight into money (no customer needed). |
| `RepairStation.cs` | Restores condition, for a price. Always works at $0 — see below. |
| `UpgradeStation.cs` | Buys another animal for a building. Remembers partial payment. Saveable. |
| `UnlockStation.cs` | Drains money to reveal new content. **Also used for every worker hire.** Saveable. |
| `DiscardStation.cs` | The bin. Throws carried goods away, gives nothing back. |
| `TravelStation.cs` | Stand 1.2 s to be faded across to another `Location`. Player only. |
| `RevealWhenAll.cs` | Reveals objects once ALL of a list of gates / upgrades / chores / empty rubbish piles / first paint job are complete. Stateless. |
| `ClearablePile.cs` | A rubbish pile: shrinks as its trash buffer empties, removes its COLLECT square when gone. |
| `PaintStation.cs` | The PAINT square: opens the paint menu; first job $1,000, repaint $200. |
| `MarketDecor.cs` | The shop's look (pattern, 3 colours, floor): applies it with MaterialPropertyBlocks, previews, saves as `market.decor`. |
| `ChoreStation.cs` | A free Task-mode job (sweep, OPEN) that hides a mess and reveals the next step. Saveable. |
| `SupplyFeed.cs` | Adds a unit to a buffer every few seconds for free (the market's storage). Saveable, with offline catch-up. |
| `CheckoutStation.cs` | The supermarket till: scans the front shopper's basket one unit per tick. Sibling of `RegisterStation`. |
| `LockedStation.cs` | A square that is labelled and measured like any other but never operational and not for sale: the market's COMING SOON bay. |

The key abstraction, from `README.md` and confirmed in the code:

> Everything in the world is either a **buffer** (a pile of goods), a **machine** (turns one
> buffer into another over time), or a **station** (a square the player stands in). Stations
> and machines never talk to each other directly — they only touch buffers.

That is what keeps new content cheap: a new building is one `BuildWorkshop()` call.

### `Player/` (namespace `Tycoon.Player`)

| File | What it is |
|---|---|
| `PlayerMotor.cs` | Movement. `CharacterController`-based. |
| `PlayerInputSource.cs` | Input abstraction — keyboard and the on-screen joystick feed the same thing. |
| `CarryStack.cs` | The stack of goods above a character's head. **Both the player and workers have one.** Mixed goods allowed. |

`CarryStack` is load-bearing architecture: `StationBase` finds its occupant by looking for a
`CarryStack` on whatever entered the trigger (`StationBase.cs:210`). That one line is why
workers need no parallel gameplay logic anywhere in the project.

| `CustomerAgent.cs` | Walks the route, holds an order, runs down its patience. Also the supermarket `Shopping` phase: browse shelves, take goods, queue with a basket. |

### `UI/` (namespace `Tycoon.UI`)

Almost all of the UI is **world-space**, not screen-space, because of the no-HUD-buttons rule.

| File | What it is |
|---|---|

| `IconFactory.cs` | **Draws every icon in code.** No icon art assets exist. |
| `UIFactory.cs` | Generates sprites and fonts at runtime (rounded boxes, circles). |

| `WorldFeedback.cs` | Floating `+$5` style popups. |

| `HudRoot.cs` | The only screen-space canvas. Bootstraps itself. Money readout, safe area, joystick, and the `ScreenFade` overlay. |

| `PaintMenu.cs` | The paint & decorate menu (colour pickers, patterns, floor, cube preview). |

## 6. Assets

### Scene
`game/Assets/_Project/Scenes/Farm.unity` — ~1.3 MB, ~550 GameObjects, **entirely generated**.
It is committed so the game is playable without running the builder, but it is an output, not a
source. The real source is `FarmSceneBuilder.cs`.

It is also the **only** scene in the build (`FarmSceneBuilder.RegisterOnlyScene()`,
`FarmSceneBuilder.cs:828`).

### Items
`game/Assets/_Project/Configs/Item_{corn,egg,hay,milk}.asset` — `ItemDefinition`
ScriptableObjects. **These are generated too**, by `LevelBuildKit.Item()` called from
`FarmSceneBuilder.CreateItems()` (`FarmSceneBuilder.cs:125-149`). Editing the `.asset` directly
works until the next scene rebuild overwrites it. **Change the values in
`FarmSceneBuilder.cs:129-147` instead.**

### Materials
`game/Assets/_Project/Materials/` — ~100 materials. Almost all are created by
`LevelBuildKit.Mat(name, color)` during a scene build. The character materials under
`Materials/Characters/` belong to the villager roles.

### Meshes
`game/Assets/_Project/Meshes/` — three generated mesh assets: `FenceLine.asset`,
`GrassCover.asset`, `TrashCan.asset`. Procedural geometry baked to assets so the scene does not
have to rebuild them at load.

### Characters
`game/Assets/_Project/Art/Characters/` — five FBX files: `Villager_Rig`, `Villager_Farmer`,
`Villager_Cashier`, `Villager_Customer`, `Villager_Owner`. See `CHARACTERS_AND_MODELS.md`.

### Animation
`game/Assets/_Project/Animation/Villager.controller` — one animator controller shared by every
character.

### Audio
**There is none.** No audio assets, no audio code beyond the `AudioListener` on the camera
(`FarmSceneBuilder.cs:790`). This is a known gap, listed in `README.md`.

## 9. What is gitignored, and why

From `.gitignore`, with its own comments:

- `game/Library/`, `Temp/`, `Obj/`, `Logs/`, `UserSettings/` — Unity's regenerable caches.
- `build-*.log` — headless build logs.
- `icon-sheet.png` — "Generated by Tycoon > Export Icon Sheet. Regenerate it rather than
  committing it."
- `models/villagers/`, `models/lowpoly/` — "Intermediate model exports; the source .glb and the
  pipeline scripts are tracked."
- `docs/` — this one matters:

  > Build output. Published to the gh-pages branch by publish.sh, never committed to main - a
  > Unity web build is ~13 MB of binaries that would be added to history on every single
  > publish.

**So `docs/` existing on disk but not in git is correct, not a mistake.**

## 10. Where `README.md` is now wrong

`README.md` was written earlier in the project's life and parts of it no longer describe the
code. It is still worth reading for design intent, but **do not trust these parts**:

| README says | Reality |
|---|---|
| "Two production wings either side of a central walking corridor" | Four short columns side by side on one street. `FarmSceneBuilder.cs:158-196`. |
| "Both tills take either product" | Counter A sells **only eggs**, counter B **only milk**. `FarmSceneBuilder.cs:267-271`. Changing this was a deliberate fix. |
| "`SaveKeys` are hierarchy paths, so renaming a station resets its state" | `SaveIdentity` replaced that. Builder-assigned ids survive renaming. `Core/SaveIdentity.cs`. |
| "Settings → Pages → branch `main`, folder `/docs`" | Pages serves the force-pushed `gh-pages` branch. `publish.sh`. |
| The unlock price table | Out of date, and **currently overridden to $10 anyway** — see below. |
| `BuildWorkshop("Bakery", root, ...)` example | The signature now takes an `id` first: `BuildWorkshop(id, name, parent, position, ...)`. |
| "Hay field ($1,800), cow shed ($2,600)" as separate purchases | The meadow is now sold **with** the first cow shed as one "Dairy" purchase, to close a softlock. `FarmSceneBuilder.cs:428-444`. |

`TWEAKING.md` is accurate and current.

## 11. ⚠ The project is currently in TEST PRICING mode

`FarmSceneBuilder.cs:44`

```csharp
private const double TestPriceOverride = 10d;
```

While this is above zero it **replaces every purchase price in the game** — land, buildings,
hires and livestock alike — with $10, so the whole progression can be walked in a couple of
minutes. The real prices are still in the code, passed through `Price(...)`.

**Set it to `0d` to restore the real economy.** This must be done before any real release.
The constant exists precisely so reverting cannot miss one (`FarmSceneBuilder.cs:43`):

> Deliberately one constant rather than edited numbers, so reverting cannot miss one.

## 13. Reading order for a newcomer

1. `TWEAKING.md` (root) — 5 minutes, tells you the scene is generated.
2. `FarmSceneBuilder.cs` — read the comments. It is the game design document in C# form.
3. `Stations/StationBase.cs` — the interaction contract everything else hangs off.
4. `LevelBuildKit.cs` — skim the public method signatures; that is the parts catalogue.
5. `EDITING_GUIDE.md` in this folder when you want to change something specific.
